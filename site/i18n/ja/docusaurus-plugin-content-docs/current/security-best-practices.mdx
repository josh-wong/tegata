## USBドライブまたはmicroSDカードの選択

物理的なメディアの品質は重要です。故障したUSBドライブはボールトファイルを破損させる可能性があり、遅いドライブはキー派生を遅く感じさせます。

### これらの特性を確認する

- **信頼できるブランド。** 確立されたメーカーのドライブを使用してください。偽造ドライブはオンラインマーケットプレイスで一般的で、容量を誤って報告したり早期に故障したりすることがよくあります。
- **書き込み耐久性。** コンシューマ用USBフラッシュドライブとmicroSDカードには有限の書き込みサイクル数があります（TLC NANDでは通常3,000〜10,000サイクル）。Tegataはクレデンシャルの変更時のみボールトに書き込み、読み取りのたびには書き込まないため、耐久性が実際の問題になることはほとんどありません。しかし、大容量ストレージ向けに販売されている非常に安いドライブは避けてください。
- **物理的な耐久性。** 金属製ケースのドライブはキーホルダーに取り付けても耐えられます。プラスチックのキャップは割れてコネクターが露出します。コネクターが収納できるか保護キャップが付いているドライブを検討してください。
- **容量。** 小さいUSBドライブ（1 GB）でも十分すぎます。数百のクレデンシャルのボールトファイルは1 MB未満です。

### 避けるべきこと

- 自動実行ソフトウェアやU3ローンチパッドを持つドライブ（古いドライブ）。これらは挿入時にコードを実行し、簡単に無効化できません。
- オークションサイトの未確認の販売者からのドライブ。クローンと偽造品が広まっています。
- 価格に対して異常に高い容量を報告するドライブ。これは偽造品の一般的な兆候です。

:::tip[バックアップを保管する]

別のUSBドライブにボールトの2番目のコピーを保管し、クレデンシャルを追加または削除するたびに更新してください。`tegata export`を使用して暗号化されたバックアップを作成します。ボールトのバックアップ方法の詳細については、[バックアップと回復](#backup-and-recovery)を参照してください。

:::

## パスフレーズの強度

パスフレーズはボールトの主な保護手段です。TegataはArgon2idを使用して暗号化キーを導出します。これによりブルートフォース攻撃のコストが高くなります。しかし、ドライブが紛失した場合、弱いパスフレーズは依然として脆弱です。

### 良いパスフレーズ

- **パスワードではなくパスフレーズを使用する。** ランダムな4つ以上の単語のシーケンス（「ダイスウェア」パスフレーズ）は、非常に記憶しやすく、解読が極めて困難です。例：`correct-horse-battery-staple`
- **少なくとも4つのランダムな単語を目指す。** 標準的な単語リストを使用すると、これにより約51ビットのエントロピーが得られます。これは、Argon2idのより安価なパラメータ設定でも、現在のハードウェアでのオフラインクラッキングの実際の範囲を超えています。
- **個人情報を避ける。** 名前、誕生日、住所、歌詞は標的型攻撃で最初に試される候補の中にあります。
- **キーボードウォークを避ける。** `qwerty`、`123456`、`zxcvbnm`のようなパターンは簡単に推測されます。

### 強度インジケーター

パスフレーズを作成または変更すると、Tegataは強度メーターを表示します。

| 評価 | 最低長 |
|--------|----------------|
| 弱い | 8〜11文字 |
| 普通 | 12〜19文字 |
| 強い | 20文字以上 |

強度メーターは文字数を代理指標として使用します。ランダムな単語の20文字のパスフレーズは、leetspeak置換を使用した20文字のキーボードウォークよりもはるかに強力です。メーターを下限として使用し、上限としては使用しないでください。

## リカバリーキーの保護

リカバリーキーはボールトを作成するときに一度だけ表示されるランダムに生成された32バイトのキーです。パスフレーズを忘れた場合にパスフレーズに依存せずにボールトを回復する方法を提供します。

:::danger[リカバリーキーは一度しか表示されません]

Tegataはボールト作成後にリカバリーキーを再表示できません。パスフレーズとリカバリーキーの両方を失った場合、ボールトを回復できません。これはあなた自身にも、誰にも、不可能です。

:::

**リカバリーキーを以下の場所のいずれかに保管してください：**

- 物理的に安全な場所に印刷して保管（金庫、施錠された引き出し、重要書類と一緒に封印した封筒、または信頼できる人の管理下）
- 別のデバイスのパスワードマネージャー（ボールトと同じUSBドライブには保管しない）

**リカバリーキーを保管してはいけない場所：**

- ボールトと同じUSBドライブ。ドライブが紛失した場合、両方が危険にさらされます。
- 暗号化なしのメールやクラウドメモサービス。
- メインコンピューターの誰でも読めるテキストファイル。

ボールトを回復せずに保存されたリカバリーキーがまだ有効であることを確認するには：

```bash
tegata verify-recovery
```

これはキーのハッシュをボールトヘッダーに保存されている値と照合し、ボールトデータを変更しません。

## バックアップと回復

ボールトファイルは小さく、簡単にバックアップできます。パスフレーズを忘れたり、外部ドライブが故障したり紛失したりした場合に備えて、バックアップルーティンを構築してください。

### 暗号化されたバックアップの作成

ボールトの暗号化されたバックアップを作成するには、以下のコマンドを実行します。パスを希望するバックアップ場所に置き換えてください。

```bash
tegata export --out /path/to/backup/vault.tegata-backup
```

Tegataはボールトパスフレーズを求め、次に独立したバックアップパスフレーズを設定するよう求めます。バックアップパスフレーズはボールトパスフレーズとは別に保管してください。同一の場合、攻撃者が一方を知ることで両方を手に入れることになります。

### バックアップからの復元

バックアップファイルからボールトを復元するには、以下のコマンドを実行します。パスをバックアップファイルに置き換えてください。

```bash
tegata import /path/to/backup/vault.tegata-backup
```

Tegataはバックアップからのクレデンシャルを現在のボールトにマージします。ラベルが既に存在するクレデンシャルは上書きを避けるためにスキップされます。

### バックアップの頻度

合理的なスケジュールは、新しいクレデンシャルを追加するたびにバックアップをエクスポートすることです。ほとんどのユーザーにとって`tegata add`は頻繁な操作ではないため、これにより負担なくバックアップを最新の状態に保てます。

## クレデンシャルの整理

タグでクレデンシャルを整理すると、ボールトが大きくなるにつれて`tegata list`とTUIクレデンシャルブラウザーのナビゲートが容易になります。

**推奨されるタグ付け規則：**

- コンテキストタグ（`work`、`personal`、`homelab`）を使用して環境ごとにクレデンシャルを分離します。
- 認証タイプでフィルタリングしたい場合はタイプタグ（`totp`、`hotp`、`static`、`cr`）を使用します。
- 関連するクレデンシャルのグループにはサービスタグ（`microsoft`、`aws`、`banking`）を使用します。

クレデンシャルを追加するときにタグを追加します。以下の例では、`personal`タグと`totp`タグを付けてMicrosoftのTOTPクレデンシャルを追加します。

```bash
tegata add Microsoft --type totp --issuer Microsoft --tag personal --tag totp
```

タグは後から追加または変更できます。

以下の例では、既存のクレデンシャルに`personal`タグと`totp`タグを追加します。

```bash
tegata tag Microsoft --add personal --add totp
```

以下の例では、`GitHub`クレデンシャルから`work`タグを削除して`archive`タグを追加します。

```bash
tegata tag GitHub --remove work --add archive
```

:::tip[非アクティブなクレデンシャルのための「archive」タグ]

積極的に使用しなくなったサービスのクレデンシャルを削除する代わりに、`archive`としてタグ付けします。再度コードが必要な場合はアクセス可能なままですが、`tegata list --tag work`を実行しても日常のビューには表示されません。

:::

## 監査ログのセキュリティとプライバシー

オプションの監査ログは、ScalarDL Ledgerのすべての認証操作を記録します。記録内容と記録しない内容を理解することは、結果の解釈と期待値の設定に重要です。

### 監査ログが記録する内容

各イベントレコードには以下のフィールドが保存されます。

- **操作タイプ。** `totp`、`hotp`、`challenge-response`、または`static`
- **ラベルハッシュ。** クレデンシャルラベルのSHA-256ハッシュ（平文ラベルではない）
- **タイムスタンプ。** Unixミリ秒（UTC）
- **イベントハッシュ。** 前のイベントにチェーンされたイベントデータのHMAC-SHA256

平文のクレデンシャル名、シークレット、生成されたコード、ボールトパスフレーズは監査ログに書き込まれません。

### `tegata verify`が証明すること

`tegata verify`はレジャーからすべてのイベントを取得し、各イベントのハッシュを保存された値と照合します。実行が成功した場合：

- イベントレコードが書き込まれてから変更されていない。
- イベントレコードが書き込まれてからレジャーから削除されていない。
- ハッシュチェーンが無傷である。

実行が成功しても、イベントが許可されたパーティによって書き込まれたこと、またはイベントのタイミングがログに記録される前に操作されなかったことは**証明しません**。監査ログは、正しく設定されたボールト上でTegataバイナリを通じて実行された操作の記録です。不正検出システムではありません。

### 監査結果の解釈

```bash
tegata history --from 2026-01-01 --to 2026-03-31
```

履歴ビューには4つの列が表示されます：操作タイプ、省略されたラベルハッシュ、タイムスタンプ（UTC）、省略されたイベントハッシュ。Tegataはボールトを読み取ることでハッシュを人間が読みやすいクレデンシャルラベルに解決します（パスフレーズの入力を求められます）。イベントが記録された後にクレデンシャルがボールトから削除されている場合、ラベルは`(deleted)`として表示されます。

`--json`を使用して出力を`jq`またはログ集計ツールにパイプします。

```bash
tegata history --json | jq '.[] | select(.operation == "totp")'
```

## キーマテリアルの処理

Tegataは使用直後に機密メモリをゼロにします。通常の使用中、RAM内のキーマテリアルを保護するための特別な手順は不要です。注意すべき関連動作は以下の通りです。

- ボールトパスフレーズはデータ暗号化キーが派生されるとすぐにゼロにされます。
- データ暗号化キーは暗号化されたインメモリエンクレーブに封印され、操作が必要なときにのみ一時的に復号されます。
- 生成されたTOTP/HOTPコードは表示またはコピーされた後、メモリに保持されません。
- クリップボードは45秒後に自動的にクリアされます（`tegata.toml`で設定可能）。
- ScalarDL Ledgerボリューム暗号化キーはセッション期間中メモリに保持され、ボールトがロックされると即座にゼロにされます。

:::warning[既知の制限事項]

デスクトップGUIでは、パスフレーズはWebViewプロセスのJavaScript文字列として一時的に保持されます。JavaScript文字列はイミュータブルで非決定論的にガベージコレクションされるため、Go側がコピーをゼロにした後も短時間パスフレーズがV8ヒープに残る場合があります。これはWebViewアーキテクチャの固有の制限であり、既知の制限として文書化されています。

:::

## USBドライブ自体のセキュリティ確保

USBドライブの物理的なセキュリティは最終的にあなたの責任です。いくつかの推奨事項：

- 使用していないときは、コンピューターに挿したままにせず、ドライブを手元（キーホルダーやランヤードなど）に保管してください。
- 信頼できないマシンでのボールトへの変更に対してハードウェアの強制を望む場合は、書き込み保護スイッチ付きのドライブを検討してください。
- コントロールしていないコンピューターにドライブを挿したままにしないでください。Tegataの暗号化されたボールトはオフラインアクセスから保護されていますが、侵害されたマシン上で実行中のTegataセッションは保護されていません。
