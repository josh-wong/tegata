# Tegata v1.0 リリースノート

このページでは、Tegata v1.0のリリースノートを説明します。新しいマイナーバージョンとパッチバージョンがリリースされると、将来のリリースノートで更新されます。

## 🚀 v1.0.0 – 初回リリース

**リリース日：** 2026年5月26日

これはTegata v1.0.0の最初のリリースです。標準のUSBドライブまたはmicroSDカードにAES-256-GCM暗号化ボールトを使用して2FAコードとクレデンシャルを保存するオープンソースのポータブル認証システムです。専用ハードウェアは不要です。

### ✨ 新機能

このリリースには以下の機能が含まれています。

#### コア認証

Tegataのオフライン対応のコアは、ネットワークアクセスなしにすべての認証操作をデバイス上でローカルに処理します。

- **TOTP/HOTPコード生成。** RFC 6238/4226準拠のコードを生成します。TOTPはSHA-1、SHA-256、SHA-512をサポートし、HOTPはSHA-1のみを使用します（[josh-wong](https://github.com/josh-wong)による[#2](https://github.com/josh-wong/tegata/pull/2)、[#94](https://github.com/josh-wong/tegata/pull/94)、[#101](https://github.com/josh-wong/tegata/pull/101)）。
	- 最初のコードの生成方法の詳細については、[最初のコードの生成](quickstart.mdx#generate-your-first-code)を参照してください。
- **チャレンジ・レスポンス署名。** サポートするサービス向けにHMAC-SHA256でチャレンジ文字列に署名します（[josh-wong](https://github.com/josh-wong)による[#3](https://github.com/josh-wong/tegata/pull/3)、[#94](https://github.com/josh-wong/tegata/pull/94)）。
	- チャレンジ・レスポンスクレデンシャルの使用方法の詳細については、[チャレンジ・レスポンスクレデンシャルとは何ですか](faq.mdx#what-is-a-challenge-response-credential)を参照してください。
- **スタティックパスワードストレージ。** OTPを使用しないクレデンシャルを保存して取得します（[josh-wong](https://github.com/josh-wong)による[#3](https://github.com/josh-wong/tegata/pull/3)）。
	- スタティックパスワードの追加方法の詳細については、[スタティックパスワードをTegataに追加できますか](faq.mdx#can-i-add-static-passwords-to-tegata)を参照してください。
- **AES-256-GCM暗号化ボールト。** Argon2id（time=3、memory=64 MiB、parallelism=4）でストレッチされたパスフレーズを使用して静止データのクレデンシャルを暗号化します（[josh-wong](https://github.com/josh-wong)による[#2](https://github.com/josh-wong/tegata/pull/2)）。
- **リカバリーキー。** パスフレーズを失った場合のボールトアクセスを回復します（[josh-wong](https://github.com/josh-wong)による[#2](https://github.com/josh-wong/tegata/pull/2)）。
	- リカバリーキーの保護方法の詳細については、[リカバリーキーの保護](security-best-practices.mdx#protecting-your-recovery-key)を参照してください。
- **memguard保護メモリ。** キーマテリアルをガードされたメモリページに保持し、使用直後にゼロにします（[josh-wong](https://github.com/josh-wong)による[#2](https://github.com/josh-wong/tegata/pull/2)）。
	- キーマテリアルの処理方法の詳細については、[キーマテリアルの処理](security-best-practices.mdx#key-material-handling)を参照してください。
- **自動ロック。** アイドル時間5分後にボールトをロックします（[josh-wong](https://github.com/josh-wong)による[#49](https://github.com/josh-wong/tegata/pull/49)、[#79](https://github.com/josh-wong/tegata/pull/79)）。
	- 自動ロックの動作の詳細については、[自動ロックの動作](tui-guide.mdx#auto-lock-behavior)を参照してください。
- **エクスポートとインポート。** ボールトのポータビリティのための暗号化バックアップファイルを作成します（[josh-wong](https://github.com/josh-wong)による[#3](https://github.com/josh-wong/tegata/pull/3)、[#68](https://github.com/josh-wong/tegata/pull/68)）。
	- 暗号化バックアップの作成方法の詳細については、[暗号化されたバックアップの作成](security-best-practices.mdx#create-an-encrypted-backup)を参照してください。
- **タグベースのクレデンシャル整理。** タグでクレデンシャルをフィルタリングおよびグループ化します（[josh-wong](https://github.com/josh-wong)による[#85](https://github.com/josh-wong/tegata/pull/85)）。
	- クレデンシャルの整理方法の詳細については、[クレデンシャルの整理](security-best-practices.mdx#credential-organization)を参照してください。

#### オプションの監査ログ

Tegataはオプションで[ScalarDL Ledger](https://github.com/scalar-labs/scalardl)（コミュニティエディション、Apache 2.0）と統合し、改ざん防止ハッシュチェーン型レジャーに認証イベントを記録します。

- 監査イベントはハッシュ化されたクレデンシャルラベルとサービス名を使用します。平文のシークレットは送信されません（[josh-wong](https://github.com/josh-wong)による[#4](https://github.com/josh-wong/tegata/pull/4)、[#80](https://github.com/josh-wong/tegata/pull/80)）。
	- 監査イベントフィールドの保護方法の詳細については、[監査ログにはどのようなデータが含まれていますか](faq.mdx#what-data-does-the-audit-log-contain)を参照してください。
- `tegata verify`はハッシュチェーンを走査して改ざんされているエントリがないことを確認します（[josh-wong](https://github.com/josh-wong)による[#16](https://github.com/josh-wong/tegata/pull/16)、[#74](https://github.com/josh-wong/tegata/pull/74)）。
	- 確認の仕組みの詳細については、[tegata verifyが証明すること](security-best-practices.mdx#what-tegata-verify-proves)を参照してください。
- オフラインイベントキューはレジャーに到達できないときに監査イベントを保存し、再接続時に再送します（[josh-wong](https://github.com/josh-wong)による[#4](https://github.com/josh-wong/tegata/pull/4)、[#27](https://github.com/josh-wong/tegata/pull/27)）。
	- Dockerがオフラインの場合のキューに入れられたイベントの動作の詳細については、[Dockerがオフラインの場合、キューに入れられたイベントはどうなりますか](faq.mdx#what-happens-to-queued-events-if-docker-is-offline)を参照してください。
- 監査スタックはDockerを通じてローカルで実行され、静止データのレジャーデータ用の暗号化バッキングボリュームを使用します（[josh-wong](https://github.com/josh-wong)による[#102](https://github.com/josh-wong/tegata/pull/102)）。
	- 暗号化されたレジャーストレージの使用方法の詳細については、[暗号化されたレジャーデータボリューム](scalardl-setup.mdx#encrypted-ledger-data-volume)を参照してください。
- ボールトごとの監査分離により、各ボールトが専用の監査コンテキストを持つことが保証されます（[josh-wong](https://github.com/josh-wong)による[#92](https://github.com/josh-wong/tegata/pull/92)）。
	- ボールトごとのScalarDLセットアップ方法の詳細については、[ScalarDLのセットアップ](scalardl-setup.mdx)を参照してください。

macOSでは、ダウンロード後に以下のコマンドのいずれかを実行してCLIバイナリを実行可能としてマークしてください。

```shell

chmod +x tegata-darwin-arm64

# Intelベースのオールマックの場合
chmod +x tegata-darwin-amd64
```

GatekeeperがGUIアプリの初回起動をブロックすることもあります。メッセージが表示された場合は、**システム設定 → プライバシーとセキュリティ → このまま開く**を使用するか、以下のコマンドで検疫を解除してください。

```shell
xattr -r -d com.apple.quarantine /Applications/Tegata.app
```
