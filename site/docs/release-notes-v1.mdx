# Tegata v1.0 release notes

This page describes the release notes for Tegata v1.0 and will be updated with future release notes as new minor and patch versions are released.

## 🚀 v1.0.0 – Initial release

**Release date:** May 26, 2026

This is the first release of Tegata v1.0.0, an open-source portable authenticator that stores your 2FA codes and credentials in an AES-256-GCM encrypted vault on a standard USB drive or microSD card. No proprietary hardware is required.

### ✨ New features

This release includes the following features.

#### Core authenticator

Tegata's offline-capable core handles all authentication operations locally on your device without network access.

- **TOTP/HOTP code generation.** Generate RFC 6238/4226-compliant codes. TOTP supports SHA-1, SHA-256, and SHA-512; HOTP uses SHA-1 only (by [josh-wong](https://github.com/josh-wong) in [#2](https://github.com/josh-wong/tegata/pull/2), [#94](https://github.com/josh-wong/tegata/pull/94), [#101](https://github.com/josh-wong/tegata/pull/101)).
	- For details on how to generate your first code, see [Generate your first code](quickstart.mdx#generate-your-first-code).
- **Challenge-response signing.** Sign challenge strings with HMAC-SHA256 for services that support it (by [josh-wong](https://github.com/josh-wong) in [#3](https://github.com/josh-wong/tegata/pull/3), [#94](https://github.com/josh-wong/tegata/pull/94)).
	- For details on how to use a challenge-response credential, see [What is a challenge-response credential](faq.mdx#what-is-a-challenge-response-credential).
- **Static password storage.** Store and retrieve credentials that don't use OTPs (by [josh-wong](https://github.com/josh-wong) in [#3](https://github.com/josh-wong/tegata/pull/3)).
	- For details on how to add static passwords to Tegata, see [Can I add static passwords to Tegata](faq.mdx#can-i-add-static-passwords-to-tegata).
- **AES-256-GCM encrypted vault.** Encrypt credentials at rest using a passphrase stretched with Argon2id (time=3, memory=64 MiB, parallelism=4) (by [josh-wong](https://github.com/josh-wong) in [#2](https://github.com/josh-wong/tegata/pull/2))
- **Recovery key.** Recover vault access if your passphrase is lost (by [josh-wong](https://github.com/josh-wong) in [#2](https://github.com/josh-wong/tegata/pull/2)).
	- For details on how to protect your recovery key, see [Protecting your recovery key](security-best-practices.mdx#protecting-your-recovery-key).
- **memguard-protected memory.** Keep key material in guarded memory pages and zero it immediately after use (by [josh-wong](https://github.com/josh-wong) in [#2](https://github.com/josh-wong/tegata/pull/2)).
	- For details on how to handle key material, see [Key material handling](security-best-practices.mdx#key-material-handling).
- **Auto-lock.** Lock the vault after 5 minutes of idle time (by [josh-wong](https://github.com/josh-wong) in [#49](https://github.com/josh-wong/tegata/pull/49), [#79](https://github.com/josh-wong/tegata/pull/79)).
	- For details on how auto-lock works, see [Auto-lock behavior](tui-guide.mdx#auto-lock-behavior).
- **Export and import.** Create encrypted backup files for vault portability (by [josh-wong](https://github.com/josh-wong) in [#3](https://github.com/josh-wong/tegata/pull/3), [#68](https://github.com/josh-wong/tegata/pull/68)).
	- For details on how to create an encrypted backup, see [Create an encrypted backup](security-best-practices.mdx#create-an-encrypted-backup).
- **Tag-based credential organization.** Filter and group credentials with tags (by [josh-wong](https://github.com/josh-wong) in [#85](https://github.com/josh-wong/tegata/pull/85)).
	- For details on how to organize credentials, see [Credential organization](security-best-practices.mdx#credential-organization).

#### Interfaces

**Terminal UI (TUI).** Offers a guided terminal interface with:

- Setup wizard for first-time vault initialization (by [josh-wong](https://github.com/josh-wong) in [#5](https://github.com/josh-wong/tegata/pull/5)).
	- For details on how to complete first launch, see [First launch and setup wizard](tui-guide.mdx#first-launch-and-setup-wizard).
- Visual countdown timer for TOTP codes (by [josh-wong](https://github.com/josh-wong) in [#5](https://github.com/josh-wong/tegata/pull/5)).
	- For details on how the countdown timer works, see [TOTP countdown timer](tui-guide.mdx#totp-countdown-timer).
- Full keyboard navigation (by [josh-wong](https://github.com/josh-wong) in [#5](https://github.com/josh-wong/tegata/pull/5)).
	- For details on how to navigate with the keyboard, see [Keyboard shortcuts](tui-guide.mdx#keyboard-shortcuts).
- Viewport-aware context menus (by [josh-wong](https://github.com/josh-wong) in [#101](https://github.com/josh-wong/tegata/pull/101)).

**Desktop GUI.** Offers a Wails + React desktop app with:

- Full feature parity with the CLI/TUI (by [josh-wong](https://github.com/josh-wong) in [#7](https://github.com/josh-wong/tegata/pull/7), [#9](https://github.com/josh-wong/tegata/pull/9))
- Installer packages for Windows, macOS, and Linux (by [josh-wong](https://github.com/josh-wong) in [#7](https://github.com/josh-wong/tegata/pull/7)).
	- For details on how to install the GUI, see [Install the GUI](gui-guide.mdx#install-the-gui).
- Vault identifier display so you always know which vault is open (by [josh-wong](https://github.com/josh-wong) in [#81](https://github.com/josh-wong/tegata/pull/81)).

#### Optional audit logging

Tegata optionally integrates with [ScalarDL Ledger](https://github.com/scalar-labs/scalardl) (Community Edition, Apache 2.0) to record authentication events in a tamper-evident, hash-chained ledger.

- Audit events use hashed credential labels and service names — no plaintext secrets are ever transmitted (by [josh-wong](https://github.com/josh-wong) in [#4](https://github.com/josh-wong/tegata/pull/4), [#80](https://github.com/josh-wong/tegata/pull/80)).
	- For details on how audit event fields are protected, see [What data does the audit log contain](faq.mdx#what-data-does-the-audit-log-contain).
- `tegata verify` traverses the hash chain to confirm no entries have been tampered with (by [josh-wong](https://github.com/josh-wong) in [#16](https://github.com/josh-wong/tegata/pull/16), [#74](https://github.com/josh-wong/tegata/pull/74)).
	- For details on how verification works, see [What tegata verify proves](security-best-practices.mdx#what-tegata-verify-proves).
- An offline event queue stores audit events when the ledger is unreachable and replays them on reconnection (by [josh-wong](https://github.com/josh-wong) in [#4](https://github.com/josh-wong/tegata/pull/4), [#27](https://github.com/josh-wong/tegata/pull/27)).
	- For details on how queued events behave offline, see [What happens to queued events if Docker is offline](faq.mdx#what-happens-to-queued-events-if-docker-is-offline).
- The audit stack runs locally via Docker and uses an encrypted backing volume for ledger data at rest (by [josh-wong](https://github.com/josh-wong) in [#102](https://github.com/josh-wong/tegata/pull/102)).
	- For details on how to use encrypted ledger storage, see [Encrypted ledger data volume](scalardl-setup.mdx#encrypted-ledger-data-volume).
- Per-vault audit isolation ensures each vault has its own dedicated audit context (by [josh-wong](https://github.com/josh-wong) in [#92](https://github.com/josh-wong/tegata/pull/92)).
	- For details on how to set up ScalarDL per vault, see [ScalarDL setup](scalardl-setup.mdx).
